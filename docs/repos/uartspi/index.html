uartspi

FPGA UART 多字节回环与独立 SPI Master，配套 Python 串口检查。

源码与 README ↗默认分支提交 ↗全部仓库

本页记录本轮维护的改动和验证结果。完整差异与实时合并状态请查看 Pull Request ↗。

准备环境使用入口目录结构检查结果

准备环境

  • python -m venv .venv
  • python -m pip install -r requirements.txt
  • Vivado 工程 use/nbytes_uart_final.xpr；根目录与 nbytes_uart_final.srcs 同名 UART 模块只编译一套。

使用入口

  • python use/main.py --help
  • python use/main.py --port COM4 --baudrate 9600 --count 100
  • python -m unittest discover -s tests -v

目录结构与职责

  • 根目录 *.v: UART 模块、旧 testbench 与独立 SPI Master
  • nbytes_uart_final.srcs/: Vivado 源/仿真/约束/IP 副本
  • use/: Vivado 工程入口及主机客户端
  • tests/: 无硬件主机回归测试
  • uart_board_top.v（两份同步）：现有时钟/RX/TX 三物理端口，FPGA 配置后4时钟启动复位；tests/uart_board_startup_tb.v：自检启动平台。

本次整理

  • 恢复两份 uart 顶层 rst_n_i 输入，移除接收总线持续 x 驱动。
  • spi_master.v 从 GB18030 转为 UTF-8，消除解析错误。
  • 主机程序改为命令行参数，默认波特率与 HDL 的 9600 一致，使用上下文管理关闭串口并拒绝非正次数。
  • 补充 README、requirements.txt、.editorconfig 和缓存忽略规则。
  • 板级 uart_board_top 保持原时钟/RX/TX 三端口，由4级初始化移位寄存器产生启动复位；不猜测或新增硬件引脚。
  • XPR 固定 uart_board_top 综合顶层，源路径相对工程目录指向实际兄弟目录，禁用旧 uart 顶层综合 checkpoint 的自动复用。

已知限制与后续工作

  • 保存的工程采用uart_board_top，仅用现有3个已约束物理端口；复位依赖Xilinx配置时寄存器初始化，只有配置后启动复位，没有按钮/看门狗/断钟恢复。单独集成uart核心需自行提供rst_n_i。
  • 剩余带符号比较、隐式调试线网、位宽告警须在参数化测试中继续评估。
  • SPI CPOL/CPHA、边界数据宽度、跨字节收发未完成行为仿真。
  • 仓库无统一 LICENSE。
  • 用户已明确同意保留9600波特/100组默认值并暂缓FPGA实机验证；启动复位仿真仍需在具备RTL模拟器的环境执行。
